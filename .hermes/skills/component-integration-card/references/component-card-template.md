# 컴포넌트 카드 템플릿 (component-card-template.md)

이 파일은 `component-integration-card` 스킬의 **4~5단계(통합 조건 정리 + 재사용 카드 완성)** 에서 사용하는 카드 템플릿이다. 완성한 카드 출력은 아래 구조를 따른다.

---

## 카드 헤더

```
[카드 N/5] <단계 상태 줄>

카드 대상:
- 부품/모듈: <부품명/관찰된 형태>
- IC: <IC명, 미확인 시 "미확인">
- 캐리어/모듈: <캐리어 제품·리비전, 미확인 시 "미확인">
- 타겟 보드: <타겟 보드/탑재 모듈>
- 적용 범위: <이 카드가 다루는 범위>
- 출처 버전: <사용한 출처와 문서 버전, 확인 날짜>
```

---

## [관찰 사실]

사용자가 직접 말한 색·표식·형태·링크·구매 정보·보드명·원하는 역할·전원 정보를 보존한다. 새 사실이 추가되면 지우지 않고 누적한다.

- ...
- ...

---

## [식별 상태]

IC와 캐리어·브레이크아웃·모듈·보드를 분리해 식별 상태를 적는다. 식별 근거 수준을 함께 적는다.

- IC: <IC명 / 미확인 / 후보>
- 캐리어/모듈: <제품·리비전 / 미확인 / 후보>
- 타겟 보드: <보드/탑재 모듈 / 미확인 / 후보>
- 식별 근거: <사진·글자·구매 링크·표식 등 근거>
- 미확인 항목: <아직 특정되지 않은 것>
- 다음 변별 증거: <식별을 확정하기 위해 필요한 추가 단서>

식별 단서만 부족하면 PROVISIONAL로 남기고, 모델별 전압·전류·주소·핀·최종 배선·직결 허용·전원 인가 행동은 주지 않는다.

---

## [확인된 자료]

출처 우선순위에 따라 대조한 자료를 적는다. 출처, 문서 버전, target, 확인 날짜를 함께 남긴다.

출처 우선순위:
1. 제조사 데이터시트·공식 제품 페이지·공식 회로도
2. 공식 개발보드 문서·공식 저장소·공식 라이브러리 예제
3. 실제 구매 페이지
4. 신뢰할 수 있는 유통사 문서
5. 블로그·포럼

- `<source>` — `<문서/페이지/절>`, version `<버전>`, target `<부품/리비전/보드>`, 확인 `<날짜>`
  - 주장: `<출처가 말하는 내용>`
  - 상태: 확인 / 계산 / 미확인
- ...

## [카드 완성도]

카드 전체 상태를 적는다.

- 카드 상태: `<PROVISIONAL / BLOCKED / VERIFIED>`
- 단계: `<N/5>`
- 정확한 IC: `<확정/미확인/후보>`
- 정확한 캐리어·리비전: `<확정/미확인/후보>`
- 정확한 타겟 보드/탑재 모듈: `<확정/미확인/후보>`
- 적용 버전 출처: `<사용한 출처와 버전>`
- 핵심 전원·전류·로직 레벨·핀 주장별 직접 근거: `<항목별 근거>`
- 미해결 안전 게이트·충돌: `<0개 / 있음>`
- 미해결 항목: `<남은 미확인/planned>`

VERIFIED는 위 항목이 모두 확정되고 미해결 안전 게이트·충돌이 0개일 때만 쓴다. 5/5는 전원 인가나 런타임 통합 시험 완료가 아니다.
