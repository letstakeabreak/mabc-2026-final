# 사용 예시 (usage-examples.md)

이 파일은 `component-integration-card` 스킬의 **교육·사용법·C1~C5 행동 검수 요청**이거나, 실제 입력이 아래 C1~C5에 매칭될 때 읽는다. 실제 입력이 매칭되면 해당 절만 읽는다.

---

## C1 — 부품을 처음 언급만 한 상태 (0/5 시작)

**입력 예**:
- "파란색 GY-521을 ESP32에 붙일 건데 부품 카드 만들어줘"
- "작은 모터인데 어디서 샀는지 모름"
- "부품 이름만 말해줌"

**想定되는 행동**:
1. `[카드 0/5] 식별 근거 수집 중`으로 시작한다. 이 줄 앞에 인사·요약·설명·판단을 쓰지 않는다.
2. `[관찰 사실]`에 사용자가 직접 말한 내용을 보존한다(부품명 일부, 색, 대략적 용도 등).
3. 식별에 필요한 추가 단서를 최대 2개 질문으로 요청한다.
   - 칩 글자와 핀 이름이 보이는 앞뒤 사진
   - 구매 링크 또는 제품명
   - 리비전·표식·포장/주문 내역
4. 식별 근거가 부족하면 모델별 전압·전류·주소·핀·최종 배선·직결 허용·전원 인가 행동은 주지 않는다.
5. 출력 뒤 `[지금 할 것]` 안에서만 최대 2개 질문을 남긴다.

**예시 출력(일부)**:
```
[카드 0/5] 식별 근거 수집 중

[관찰 사실]
- 사용자가 파란색 보드라고 말함
- GY-521이라고 칭함
- 타겟: ESP32(추정)

[식별 상태]
- PROVISIONAL
- IC·캐리어·리비전·타겟 보드 모두 미확인

[확인된 자료]
- 없음

[확인된 전기 조건]
- 없음

[현재 차단 항목]
- 없음

[지금 할 것]
- 칩 글자와 핀 이름이 보이는 앞뒤 사진을 준비한다.
- 가능하면 구매 링크나 제품명을 알려준다.

[카드 완성도]
- PROVISIONAL
```

## C2 — 관찰 사실은 있지만 출처가 아직 없는 상태 (1/5~2/5 진입 검토)

**입력 예**:
- "파란색 보드에 칩 글자로 MPU-6050이 보임. 4핀이고 I2C로 쓸 거고 3.3V 쓸 예정"
- "사진과 제품명은 있음"

**想定되는 행동**:
1. 관찰 사실을 `[관찰 사실]`에 보존한다.
2. IC(MPU-6050)와 캐리어(GY-521)를 분리한다.
3. 타겟 보드를 분리한다(ESP32 모듈/개발보드 구분).
4. 출처 우선순위에 따라 대조 준비를 한다.
   - 제조사 데이터시트·공식 제품 페이지·공식 회로도
   - 공식 개발보드 문서·공식 저장소·공식 라이브러리 예제
   - 실제 구매 페이지
   - 신뢰할 수 있는 유통사 문서
   - 블로그·포럼
5. 아직 출처 대조가 끝나지 않았으면 `[확인된 자료]`를 확정하지 않고, 출처 대조 계획/필요 자료를 남긴다.
6. 전압·전류·로직 레벨·핀 주장을 출처에서 확인하기 전에는 모델별 수치를 단정하지 않는다.
7. 출처 충돌이 있으면 `[확인된 자료]`나 별도 영역에 5열 표로 남긴다.

**예시 출력(일부)**:
```
[카드 1/5] IC·캐리어·타겟 후보 분리

[관찰 사실]
- 파란색 보드
- 칩 글자: MPU-6050
- 핀 4개
- I2C 용도
- 3.3V 사용 예정
- 타겟 보드: ESP32(추정)

[식별 상태]
- PROVISIONAL
- IC 후보: MPU-6050
- 캐리어 후보: GY-521(추정)
- 타겟 보드: ESP32(추정) — 모듈/개발보드 구분 필요
- 미확인: 리비전, 정확한 캐리어 제품, 공식 출처

[확인된 자료]
- 없음 (출처 대조 전)

[확인된 전기 조건]
- 없음 (출처 대조 전)

[현재 차단 항목]
- 없음

[지금 할 것]
- 제조사 데이터시트 또는 공식 제품 페이지를 확인한다.
- 구매 링크가 있으면 공유한다.

[카드 완성도]
- PROVISIONAL
```

## C3 — 출처 대조를 시작한 상태 (2/5)

**入力 예**:
- "공식 자료/구매 링크를 일부 찾음"
- "값과 출처가 몇 개 있음"

**想定되는 행동**:
1. 출처 우선순위에 따라 확인한 자료를 `[확인된 자료]`에 정리한다.
2. 각 값 옆에 출처·문서 버전·target·확인 날짜를 남긴다.
3. 확인/계산/미확인을 구분한다.
   - 출처에서 직접 확인한 값 → 확인
   - 확인된 값과 명시한 가정으로 계산한 값 → 계산
   - 근거가 없거나 변형에 따라 달라지는 값 → 미확인
4. 출처 충돌은 5열 표로 남긴다.
   `source | claim | target | conflict | unblock`
5. 미해결 안전 출처 충돌이 있으면 BLOCKED, [카드 3/5] 진입 불가.

**예시 출력(일부)**:
```
[카드 2/5] 정확한 출처 대조

[관찰 사실]
- (이전 관찰 사실 유지)

[식별 상태]
- PROVISIONAL / (특정되면 갱신)

[확인된 자료]
- 제조사 데이터시트, MPU-6050, 동작 전압 범위, 확인 <날짜> — 상태: 확인
- 구매 페이지, GY-521, "5V 가능" 문구, 확인 <날짜> — 상태: 확인(외형/문구), 전기 수치 최종 근거로는 미확인

[출처 충돌]
- source: 구매 페이지 / claim: 5V 사용 가능 / target: GY-521 + ESP32 3.3V 사용 / conflict: 내부 IC 동작 전압·절대 최대 정격과 충돌 가능성 / unblock: 제조사 공식 데이터시트 리비전, 캐리어 레귤레이터/레벨 시프터 확인

[확인된 전기 조건]
- 일부 값 확인/계산/미확인으로 분리 (단정 금지)

[현재 차단 항목]
- 미해결 안전 출처 충돌 시 BLOCKED

[지금 할 것]
- 내부 IC 동작 전압·절대 최대 정격·캐리어 레귤레이터/레벨 시프터 확인
- 타겟 보드 공급 한계 확인

[카드 완성도]
- PROVISIONAL
```

## C4 — 전기 호환성 판정 단계 (3/5)

**入力 예**:
- "출처 대조가 끝났고 미해결 안전 충돌이 없음"
- "전원·전류·로직 레벨 값을 확보한 상태"

**想定되는 행동**:
1. 모듈 입력 전압, IC 동작 전압, 로직 레벨, 일반 소비 전류, 최대·피크 전류, 대상 보드 공급 한계, 직결/레벨 변환/보호 필요 여부를 대조한다.
2. 각 항목을 확인/계산/미확인으로 정리한다.
3. 절대 최대 정격을 권장 동작 조건으로 바꾸지 않는다.
4. IC 데이터시트로 캐리어 VIN·레귤레이터·레벨 시프터·핀 배치를 확정하지 않는다.
5. 전원/GND·극성·핀 방향을 확인한다.
6. 직결/레벨 변환/보호 필요 여부를 검토한다.
7. I2C 등 버스 사용 시 주소·풀업·버스 전압·다중 장치를 검토한다.
8. 미해결 게이트/충돌이 0개면 [카드 4/5]로, 아니면 BLOCKED.

**예시 출력(일부)**:
```
[카드 3/5] 전기 호환성 판정

[관찰 사실]
- (이전 관찰 사실 유지)

[식별 상태]
- (이전 식별 상태 유지, 확정된 것은 확정으로)

[확인된 자료]
- (2단계 출처 대조 유지)

[확인된 전기 조건]
- 모듈 입력 전압: <값>, <출처>, 상태: 확인/계산/미확인
- IC 동작 전압: <값>, <출처>, 상태: 확인/계산/미확인
- 절대 최대 정격: <값>, <출처>, 상태: 확인
- 권장 동작 조건: <값>, <출처>, 상태: 확인
- 로직 레벨: <값>, <출처>, 상태: 확인/계산/미확인
- 일반 소비 전류: <값>, <출처>, 상태: 확인/계산/미확인
- 최대/피크 전류: <값>, <출처>, 상태: 확인/계산/미확인
- 타겟 보드 공급 한계: <값>, <출처/가정>, 상태: 확인/계산/미확인
- 전원/GND/극성/핀 방향: <planned/확인/미확인>
- 직결/레벨 변환/보호: <planned/확인/미확인>
- 버스 게이트: <I2C 주소/풀업/버스 전압/다중 장치>, 상태: 확인/계산/미확인

[현재 차단 항목]
- 없음 또는 BLOCKED 사유

[지금 할 것]
- 최종 핀 맵 정리
- 전원/GND/버스 경로 정리
- 필수 드라이버/보호 소자 정리
- 소프트웨어 선행 조건 정리

[카드 완성도]
- PROVISIONAL 또는 VERIFIED 준비
```

## C5 — 통합 조건 정리 및 카드 완성 (4/5~5/5)

**入力 예**:
- "전기 호환성 게이트 통과, BLOCKED 0개"
- "최종 핀 맵·전원/GND/버스 경로·드라이버/보호·소프트웨어 선행 조건을 정리 가능한 상태"

**想定되는 행동**:
1. 최종 핀 맵을 정리한다.
2. 전원/GND/버스 경로를 정리한다.
3. 필수 드라이버/보호 소자를 정리한다.
4. 소프트웨어 선행 조건을 정리한다.
5. 각 항목을 확인/계산/미확인/planned로 남긴다.
6. 결정적 PROVISIONAL/BLOCKED/충돌이 0개면 [카드 5/5]로 완성한다.
7. 5/5는 전원 인가나 런타임 통합 시험 완료가 아니다.

**예시 출력(일부)**:
```
[카드 4/5] 통합 조건 정리

[관찰 사실]
- (이전 관찰 사실 유지)

[식별 상태]
- (확정 사항 반영)

[확인된 자료]
- (출처 대조 유지)

[확인된 전기 조건]
- (3단계 정리 유지, planned 항목 포함)

[현재 차단 항목]
- 없음

[지금 할 것]
- 최종 배선/전원 인가 전 확인 항목
- 필요시 구매 링크/데이터시트 재확인

[카드 완성도]
- PROVISIONAL → VERIFIED 준비

[카드 5/5] 재사용 카드 완성

[관찰 사실]
- (누적된 관찰 사실)

[식별 상태]
- VERIFIED (정확한 IC·캐리어·리비전·타겟 보드 확정 시)

[확인된 자료]
- (출처·버전·target·확인 날짜 포함)

[확인된 전기 조건]
- (전원·전류·로직·극성·GND·핀·버스 게이트별 근거)

[현재 차단 항목]
- 없음

[지금 할 것]
- 실제 배선/전원 인가 전 확인
- 필요시 추가 시험

[카드 완성도]
- VERIFIED
- 정확한 IC: 확정
- 정확한 캐리어·리비전: 확정
- 정확한 타겟 보드/탑재 모듈: 확정
- 적용 버전 출처: 명시
- 핵심 전원·전류·로직 레벨·핀 주장별 직접 근거: 있음
- 미해결 안전 게이트·충돌: 0개
- 미해결 항목: 없음
```

**주의**: 5/5는 전원 인가나 런타임 통합 시험 완료가 아니다. 카드는 재사용 가능한 정리 결과로 남는다.

## 공통 행동 검수 체크리스트(C1~C5 공통)

- 첫 사용자 가시 문장은 항상 상태 줄이다. 상태 줄 앞에 인사·요약·설명·판단을 쓰지 않는다.
- 매 답변에서 일곱 구역을 각각 별도 줄과 별도 문단으로 이 순서대로 출력한다.
  - `[관찰 사실]`
  - `[식별 상태]`
  - `[확인된 자료]`
  - `[확인된 전기 조건]`
  - `[현재 차단 항목]`
  - `[지금 할 것]`
  - `[카드 완성도]`
- 각 제목 줄에는 값을 적지 않고, 다음 문단에서 내용을 적는다.
- 빈 구역은 "없음" 또는 "미확인"으로만 남긴다.
- 질문은 일곱 구역 밖에 별도 문단으로 붙이지 말고 `[지금 할 것]` 안에서만 최대 2개다.
- IC와 캐리어를 분리한다.
- 후보는 최대 2개까지 제시하고 근거·출처·유력/미확인 상태를 붙인다. 외관이 닮았다는 이유만으로 전압·핀맵을 가져오지 않는다.
- 출처 우선순위를 지킨다.
- 절대 최대 정격을 권장 동작 조건으로 바꾸지 않는다.
- 출처 충돌은 5열 표로 남긴다.
- 실제 측정/연결/배선/전원 인가를 대행하지 않는다. 카드는 재사용 가능한 정리 결과로 남긴다.
