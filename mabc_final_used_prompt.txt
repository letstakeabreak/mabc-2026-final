Question:
? Clarify: 웹 대시보드에서 가장 먼저 필요한 것은 무엇인가요? → 카드 생성 위클리 단일 페이지: 관찰 사실 입력 → 카드 상태(0/5~5/5) 표시 → 일곱 구역 출력 → 완료된 카드 목록 저장·열람 (로컬스토리지 기반, 백엔드 없음) (Recommended)

? Clarify: 백엔드나 스킬 연동은 언제/어떻게 붙일 계획인가요? → 나중에 백엔드/스킬 연동을 염두에 둔 프론트엔드 프로토타입(API 호출 자리 표시 포함)

? Clarify: 디자인 톤/제약은 있나요? (예: 다크/라이트, 대회 제출용이라 간결해야 함, 모바일 대응 필요 여부 등) → 다크/라이트 대응 해줬으면 좋겠고, 모바일 대응도 해 주고, 좀 간결해야 하기는 해. 그래도 디자인 자체는 Human Interface Guideline을 참고해서 깔끔하게 만들어 줘.

일단 이걸 커밋해줄래?

---

앞으로 커밋은 최대한 자잘하게 커밋할 예정이야. 대회 규정이 개발 기록을 보는 거고. branch를 만들게 되면 나중에 문제가 될 수있기 때문에, 일단 branch 없이 convention 잘 지켜가면서 커밋하는 쪽으로 진행하도록 하자.

---

IDE 형식을 차용한 Dashboard 형태였으면 좋겠어. 결국 임베디드 개발이다보니 터미널을 사용해야 하기도 하고, 코드 편집도 
가능해야 하니까..

---

? Clarify: IDE 레이아웃에서 카드 대시보드는 어떻게 배치할까요? → 사이드바(파일 트리/카드 목록/설정) + 상단 탭 영역(코드 편집기 / 카드 대시보드 / 터미널) + 하단 터미널 패널 (Recommended)

? Clarify: 코드 편집기는 어느 정도로 만들까요? (외부 라이브러리 없이 단일 HTML 파일 범위) → 텍스트에어리어 기반 편집기 + 좌측에 줄번호 표시 (탭/들여쓰기 지원, 구문 강조는 없이 깔끔하게) (Recommended)

? Clarify: 터미널은 어떤 범위로 만들까요? → 시뮬레이션 터미널: 명령어 입력 + 출력 로그 + ↑/↓ 히스토리 + localStorage 세션 보존. 실제 시리얼/플래시 연동은 추후 자리 표시 (Recommended)

? Clarify: 카드 생성/목록 기능은 IDE 안에서 어떻게 유지하나요? → 카드 생성/목록 기능은 기존대로 유지하되, IDE 안에 탭/패널로 통합 (Recommended)
